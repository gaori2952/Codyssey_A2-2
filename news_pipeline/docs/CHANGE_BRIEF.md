# 현재 구현 변경점 브리핑

## 한 줄 요약

초기 목표였던 단일 뉴스 수집·요약 도구가 여러 소스를 모아 동일 이슈를 찾고, 소스별 보도 차이를 비교하는 분석 파이프라인으로 확장되었다.

## 초기 목표와 현재 구현

| 구분 | 초기 목표 | 현재 구현 |
|---|---|---|
| 수집 | RSS 1개, 크롤링 1개 | 여러 RSS와 crawl 소스 설정 |
| RSS | 공개 IT RSS 수집 | 공통 주제 Google News RSS 2개로 관련 기사 수집 |
| 소스 정보 | 수집 소스 저장 | RSS가 제공하는 실제 발행 매체명을 source로 저장 |
| 중복 | 같은 URL skip/upsert | URL 중복과 다른 URL의 동일 이슈를 분리 |
| 저장 | raw_news, clean_news, analyses | issues 테이블과 issue_id, 비교 분석 컬럼 추가 |
| 정제 | HTML·공백·날짜·결측값 처리 | 기존 정제 + 키워드 카테고리 분류 + 이슈 그룹화 |
| AI | 개별 뉴스 요약 | 기존 요약 + 전체 트렌드 분석 + 소스 비교 분석 |
| 분석 | 전체 뉴스 트렌드 | 전체 트렌드와 특정 이슈/전체 비교 분석을 분리 |
| CLI | 기본 fetch/clean/summarize/analyze/report/export | 기존 명령 유지 + `analyze --issue`, `analyze --compare` 추가 |
| 리포트 | 통계와 AI 분석 Markdown | 표 중심 통계, 3개 차트, 소스 비교표, TXT/MD 비교 파일 |
| 시각화 | 카테고리·일자별 2개 차트 | 기존 2개 유지 + 소스별 기사 수 차트 추가 |
| Export | CSV, Excel | 기존 형식 유지 + source/category/issue_id/summary 포함 |
| API | API Key 환경변수 | Codyssey `requests.post` 방식, 키 미설정·형식 오류 안내 |

## 핵심 기능 변화

### 1. 단일 소스에서 다중 소스로 변경

초기에는 일반 RSS와 Hacker News를 각각 읽었다. 일반 피드는 서로 다른 사건이 섞여 동일 이슈 비교가 잘 생기지 않는 문제가 있었다. 현재는 OpenAI/AI 모델처럼 공통 주제를 여러 RSS 검색으로 수집하여 비교 가능한 기사 후보를 만들도록 변경했다.

### 2. 중복 뉴스와 동일 이슈를 분리

- 중복 뉴스: URL이 같으면 `skip` 또는 `upsert`
- 동일 이슈: URL은 다르지만 제목·본문 키워드·카테고리가 유사하면 같은 `issue_id`

따라서 서로 다른 매체의 같은 사건은 삭제하지 않고 비교할 수 있다.

### 3. DB migration으로 기존 데이터 보존

기존 `news.db`를 삭제하거나 다시 만들지 않는다. 실행 시 `issue_id`, `analysis_type`, `comparison_result`가 없으면 `ALTER TABLE`로 추가한다. 기존 뉴스와 요약 결과는 보존된다.

### 4. 분석 결과를 두 종류로 분리

- 전체 뉴스: 주요 트렌드, 핵심 키워드, 공통 이슈, 시사점
- 동일 이슈: 공통 사실, 소스별 강조점, 표현·제목 차이, 핵심 키워드 차이, 관점·종합 시사점

비교 결과는 `CNBC | Politico` 형태의 표로 출력하며 공통 사실은 표 안에서 한 번만 표시한다.

### 5. 리포트 가독성 개선

초기 리포트의 긴 문장을 표와 bullet 중심으로 바꾸었다.

- 핵심 지표 표
- 카테고리 TOP 5 표
- 상위 뉴스 소스 5개와 `기타` 묶음
- 트렌드와 시사점 bullet
- 소스별 비교 HTML 표
- Markdown 안에 차트 이미지 삽입

## 실제 검증된 상태

- Raw 뉴스와 Clean 뉴스 저장 확인
- 기존 29건 데이터와 요약 결과 보존 확인
- 비교 가능한 이슈 1건 생성 확인
- CNBC와 Politico의 서로 다른 강조점 비교 결과 저장 확인
- `report.md`에 한국어 비교표 생성 확인
- `category_count.png`, `daily_news_count.png`, `source_count.png` 생성 확인
- CSV와 Excel 생성 확인
- Python 문법 검사 통과

## 현재 한계

- 동일 이슈 그룹화는 머신러닝이 아니라 제목·키워드 기반의 단순 규칙이다.
- 기사 본문이 충분하지 않은 RSS 항목은 비교 내용이 제목·요약 중심일 수 있다.
- 기존에 영어로 저장된 비교 결과는 새 비교 API를 다시 실행해야 완전히 한국어로 갱신된다.
- 뉴스 사이트 구조나 RSS 정책이 바뀌면 `config.json` 또는 수집 선택자를 수정해야 한다.
