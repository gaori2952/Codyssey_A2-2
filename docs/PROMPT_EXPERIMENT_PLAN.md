# 프롬프트 개선 실험 계획

## 1. 목적

AI 요약과 분석 결과는 프롬프트 표현 방식에 따라 정확도, 일관성, 길이, 비용이 크게 달라질 수 있습니다. 본 문서는 기존 프롬프트를 기준으로 개선 프롬프트를 설계하고, 실험을 통해 최적안을 찾는 절차를 정리한다.

## 2. 기존/개선 프롬프트 비교

### 기존 프롬프트 특징

- 요약은 짧고 단순한 규칙 중심
- 분석은 키를 명시하지만 표현을 자유롭게 허용
- 비교는 지시가 길고, 출력을 분석형 JSON으로 요구하지만 실제 세부 기준은 다소 모호함

### 개선 프롬프트 특징

- 금지사항을 명시적으로 추가
- 기대 출력 구조를 더 구체화
- 기사에 없는 내용 추론 금지
- 결과 길이와 필수 항목을 제한
- 소스별 비교에서 강조점과 표현 차이를 분리해서 요구

예시 비교:

```text
기존: "뉴스를 요약하세요."
개선: "주어진 기사 본문만 바탕으로 핵심 사실 3문장 이내로 요약하세요. 추정, 루머, 광고 문구, 기사 외 정보는 넣지 마세요."
```

## 3. 평가 기준

다음 기준으로 프롬프트를 비교한다.

- 정확성: 사실과 뉴스 본문의 일치 정도
- 핵심정보 포함률: 기사 핵심 메시지의 누락 여부
- 일관성: 같은 입력에 대해 비슷한 결과를 반복적으로 생성하는지
- 길이: 너무 짧거나 너무 긴 결과인지
- 구조화: JSON 파싱이 가능한지, 키 누락이 없는지
- 비용 효율성: 입력/출력 토큰 사용량과 품질의 균형

## 4. 실험 설계

### 4.1 평가 데이터셋

- 실제 수집된 뉴스 20~50건
- 서로 다른 카테고리와 길이의 기사 포함
- 기사별로 핵심 사실을 수동 라벨링
- 동일 이슈 비교를 위한 5~10개 기사 세트 준비

### 4.2 실험 조건

1. 기존 프롬프트 기준 실행
2. 개선 프롬프트 A: 규칙 강화형
3. 개선 프롬프트 B: 구조화 JSON 중심형
4. 개선 프롬프트 C: 비용 효율형(짧은 입력, 짧은 출력)

## 5. 측정 방법

- 각 프롬프트를 동일 기사 집합에 적용
- 결과물을 수동 리뷰로 정확도 점수화
- JSON 파싱 성공 여부 확인
- 출력 길이를 문자 수와 토큰 수로 비교
- 비용과 품질의 Trade-off를 함께 기록

예시 메트릭:

```text
정확성: 0~5점
핵심정보 포함률: 0~5점
일관성: 0~5점
길이 적합성: 0~5점
구조화 성공률: %
```

## 6. 기대 효과

개선 프롬프트는 다음을 기대합니다.

- 추론형 오답 감소
- 핵심 사실 누락 감소
- JSON 응답 안정성 향상
- 비교 분석의 간결성과 재현성 개선
- 동일 이슈 비교에서 소스별 차이 표현의 일관성 증가

## 7. 운영 방안

- 정기적으로 새 프롬프트 버전과 평가 결과를 문서화
- 모델 업그레이드 또는 API 변경이 있을 때 실험을 재실행
- 성능이 비슷하면 비용이 낮은 버전을 기본값으로 채택
- 합격 기준을 초과하는 프롬프트만 프로덕션에 적용

## 8. 결론

프롬프트 개선은 단순히 문장만 다듬는 일이 아니라, 수집된 뉴스의 품질과 비용, 최종 보고서의 신뢰성을 함께 제어하는 핵심 작업입니다. 이 실험 계획을 통해 모델 사용 효율과 결과 품질을 균형 있게 관리할 수 있습니다.
