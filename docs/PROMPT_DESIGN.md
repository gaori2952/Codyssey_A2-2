# 프롬프트 설계 문서

## 1. 프롬프트 설계 이유

이 프로젝트는 뉴스 수집·정제·분석 파이프라인에서 AI 요약과 비교 분석을 수행합니다. 단순히 모델에 뉴스 내용을 던져주는 것만으로는 결과 품질이 불안정할 수 있으므로, 다음 목적에 맞게 프롬프트를 설계합니다.

- 기사에 없는 내용 추론 방지
- 사실 중심의 요약과 분석 유지
- 소스별 차이 비교를 구조화하여 정량적 비교 가능하게 만들기
- 동일 이슈 비교 시 서술과 강조 포인트를 일관되게 추출하기
- 출력 형식을 JSON으로 고정해 후속 파싱 오류를 줄이기

핵심 전략은 "모델에 해야 할 일, 금지할 일, 출력 구조를 명확히 제시하는 것"입니다.

## 2. 기대 출력 형태

### 2.1 요약 프롬프트

입력:
- 기사 제목
- 기사 본문

출력:
- 3문장 이내
- 한국어 사실 중심 서술
- 추정/추론 금지

예상 형식:

```text
요약: ...
```

### 2.2 분석 프롬프트

입력:
- 여러 기사 요약 목록

출력:
- JSON 객체
- 키: `trend`, `keywords`, `issues`, `implications`

예시:

```json
{
  "trend": "...",
  "keywords": "...",
  "issues": "...",
  "implications": "..."
}
```

### 2.3 비교 프롬프트

입력:
- 동일 이슈의 여러 기사 정보

출력:
- JSON 객체
- 키: `common_facts`, `source_emphasis`, `expression_differences`, `keyword_differences`, `perspective_implications`

예시:

```json
{
  "common_facts": ["..."],
  "source_emphasis": {"A매체": "...", "B매체": "..."},
  "expression_differences": ["..."],
  "keyword_differences": ["..."],
  "perspective_implications": ["..."]
}
```

## 3. 입력/출력 예시

### 3.1 요약 입력 예시

```text
제목: OpenAI, 새 모델 공개
본문: ...
```

출력 예시:

```text
OpenAI가 새 AI 모델을 공개하면서 업계 경쟁이 가속화되고 있다. 공개된 모델은 기존 제품 대비 추론 속도와 효율성을 개선했다. 다만 실제 서비스 적용 시 비용과 검증 절차에 대한 논의가 계속되고 있다.
```

### 3.2 분석 입력 예시

```text
제목: ...
요약: ...

제목: ...
요약: ...
```

출력 예시:

```json
{
  "trend": "AI 모델 경쟁이 고성능 추론과 비용 효율성으로 이동하고 있다.",
  "keywords": "추론 속도, 비용 최적화, 모델 공개, 기업 적용",
  "issues": "모델 성능 향상과 실제 서비스 적용 사이의 간극이 주된 논쟁이다.",
  "implications": "기업은 인프라 비용과 운영 안정성을 함께 고려해야 한다."
}
```

## 4. 프롬프트 버전 관리 방법

프롬프트는 모델 결과 품질이 변경될 수 있으므로 버전 관리가 필요합니다.

권장 방법:

- `docs/prompts/` 아래에 버전별 파일로 관리
- 예: `v1_summary_prompt.md`, `v2_summary_prompt.md`
- 업데이트 시 변경 목적과 기대 효과를 주석 또는 문서에 기재
- 모델 응답 샘플을 함께 저장해 비교 가능하게 만들기
- 정기적으로 기준 샘플을 재실행해 버전 간 품질을 비교

예시 구조:

```text
docs/
  prompts/
    v1_summary_prompt.md
    v2_summary_prompt.md
    v1_analysis_prompt.md
    v2_analysis_prompt.md
```

버전 기록 항목:

- 변경 날짜
- 변경 이유
- 목적
- 결과 비교 기준
- 평가 기준 점수

## 5. 요약

이 프로젝트의 프롬프트 설계는 단순한 문장 생성이 아니라, 구조화된 결과를 얻기 위한 정합성 확보 작업입니다. 모델이 잘못 추론하지 않도록 제한하고, JSON 형식으로 답하도록 강제하면 후속 파이프라인 안정성이 크게 향상됩니다.
